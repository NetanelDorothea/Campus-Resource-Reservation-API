I learned that backend development are the proccesses behind the user interface such as payment processing, database management, security etc. Backend is essential to make a working system. Furthermore, I learned that thinking cricitially on the choices for the backend design is important for application flow such as security risks, busines rules, speed of application, and responses to growth and failure.

# What you learned about working with a shared codebase
Working in Github I learned that working in a shared coding environment requires clear and effective communication, structured code, and critical thinking. These are essential because it helps teams collaborate better. Backend code can get complicated quickly and it can be hard for anyone to understand how the system works without proper explanation. Lack of proper communication could be detrimental to maintainance and updates for the system, especcially when new code from different members have to be joint together. Not having structured code also makes debugging harder because developers would have to figure out what the system is supposed to do and spend hours trying to understand the code. 


# One technical challenge you solved
One technical challenge I solved is finding bugs. While working on a backend systems it is almost inevitable to encounter problems in code. These bugs are sometimes easy to find, and sometimes they take a longer time to fix. One instance would be where the appication wouldn't connect with certain middleware such as an error handler. This was frustrating at first, but the way I tackled this problem was through really trying to understand what was happening in my code step by step. I even added some temprorary logs in javascript to be able to trace everything. This made it easy for me to spot bugs.   


# One area you would improve if you had more time
If I had more time, I would work on more features such as admin functions. Currently users are able to create accounts and log in. However, the admin is not able to delete or modify users. This functionality is crucial because it allows for mistakes to be fixed in a protected way without having to enter the sourcecode. 
Additionally, I would work on more specific error messages, not general error handling, to make it a little bit more user friendly. This functionality would be effecient because the user then knows what went wrong exactly.
